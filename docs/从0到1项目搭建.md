# Hello，小A：从 0 到 1 的项目搭建

这份文档用于快速了解项目如何从问题定义、前期调研和方案设计，逐步落地为可运行、可验证、可部署的企业知识工作流 Agent。

## 1. 从真实问题出发

企业知识工作者常需要在文档、客户信息、工单和邮件之间反复切换：信息难找、流程断裂、敏感操作缺少控制。本项目将目标收敛为一条可闭环的主链路：

> 用户用自然语言提出问题 → 系统检索知识或识别业务意图 → 多 Agent 协作完成分析/执行 → 高风险操作进入审批 → 全过程可审计、可恢复。

由此确定了四项不可缺少的能力：可靠知识问答、受控工具调用、多角色权限隔离，以及可观测的工程运行能力。

## 2. 前期准备：从调研到方案

在编码前，先完成了行业调研、产品定义与技术方案收敛。

| 阶段 | 核心产出 | 解决的问题 |
|---|---|---|
| 需求与行业调研 | 企业 Agent、RAG、工作流自动化调研 | 明确知识检索与业务执行需要形成闭环 |
| 产品方案 | 用户角色、业务场景、审批和审计要求 | 将“聊天机器人”收敛为企业知识工作流 Agent |
| 技术方案迭代 | LangGraph 编排、RAG、工具契约、评测与安全设计 | 为多 Agent 协作和可控执行建立工程边界 |
| 方案复审 | 风险项、优先级和改进清单 | 把功能目标拆成可验证的研发任务 |

前期调研、产品方案、技术方案与复审改进项已在本文中归并为上述建设路径，避免读者在多份历史材料之间反复跳转。

## 3. 实现路径：搭建一条可验证的 Agent 主链路

项目没有直接堆叠功能，而是按依赖关系逐层搭建。

| 建设层 | 关键实现 | 结果 |
|---|---|---|
| 基础设施 | Docker Compose、PostgreSQL、Redis、Milvus、本地模型与配置体系 | 开发、测试和部署有一致的运行底座 |
| 知识能力 | 文档入库、向量检索、重排、置信度判断和降级链 | 回答可基于企业知识，而非自由编造 |
| 评测能力 | 评测集、检索与回答验证脚本 | 每次迭代可以回归验证核心能力 |
| 多 Agent 编排 | Planner、Knowledge、Analysis、Execution 与 Aggregator | 多意图任务可拆解、并行执行并汇总 |
| 状态恢复 | Redis Checkpointer、会话状态与人工介入 | 对话流程可追踪、可恢复 |
| 工具执行 | CRM、邮件、工单工具；Saga 补偿 | Agent 能完成受控业务动作 |
| 安全与审批 | JWT、RBAC、命名空间隔离、审批、审计与限流 | 敏感操作具备权限和人审边界 |
| 生产化 | 健康检查、追踪、监控、生产 Compose 与部署文档 | 项目可从本地演示走向可部署服务 |

## 4. 核心架构

```text
用户请求
  └─ API / 认证 / 限流
       └─ Planner（识别意图、拆分任务）
            ├─ KnowledgeAgent（RAG 问答）
            ├─ AnalysisAgent（数据分析）
            └─ ExecutionAgent（工具调用、审批、Saga）
                 └─ CRM / 邮件 / 工单
       └─ Aggregator（统一生成结果）

Redis：会话状态与限流   PostgreSQL：业务、审批、审计
Milvus：知识向量检索    OpenTelemetry：链路观测
```

设计重点不是让模型“尽可能自由”，而是让每一层都有边界：Planner 负责路由，工具层负责最终授权，审批层负责高风险动作，审计层负责留下可追溯记录。

## 5. 从功能到闭环

最终项目可覆盖以下完整流程：

1. 用户查询企业制度、产品知识等内容，系统通过 RAG 给出有来源约束的回答。
2. 用户提出数据分析或多步骤业务需求，Planner 将任务分配给相应 Agent。
3. ExecutionAgent 只看到当前角色允许使用的工具，并在执行前再次校验权限。
4. 外部邮件等高风险操作会创建审批单；批准后才继续执行。
5. 多步骤执行失败时，通过 Saga 做反向补偿；操作、审批与异常均写入审计记录。

项目交付不止是界面演示，还包括：

- 端到端验证：认证、RAG、闲聊、历史恢复、权限负例、审批与工具执行等主流程均有验证覆盖。
- 部署能力：提供 Docker Compose、生产部署说明、健康检查、备份与监控接入说明。
- 可体验界面：浏览器端支持角色登录、流式对话、业务数据查看、审批处理、反馈与系统状态查看。
- 文档体系：产品文档、使用案例、运维手册、前置方案与阶段总结均纳入仓库。
